# 订单管理

入口：运输管理 → 订单管理（`/orders.html`）。沿用工作台登录和两个现有管理员的权限。

订单保存至 `freight_booking_orders`；不导入预览站的本地样例，不改动旧 `orders/customers/quotes` 表。托书、收发通、包装、服务要求、费用和操作记录同票保存。修改采用版本检查，发生冲突时拒绝覆盖并保留未提交表单。

每次读取100票，按需“加载更多订单”；前端每页20票。搜索、筛选及统计针对已加载订单。通知人同收货人按实时资料展开。重量、体积在明细完整时汇总，否则保留填写的托书总数。

本次范围：新建/编辑/查看、批量状态、CSV导出、操作记录、应收预估费用。自动Excel解析、附件上传、邮件发送、采购成本及正式结算联动尚未接入，页面如实提示。原型费用只能作为待确认应收，不作为正式发票。

`orders-ui` 为可维护的React源文件，`build-orders.mjs` 构建脚本输出独立JS/CSS并限定样式作用域。所有私有页面仍经服务器鉴权和工作台登录引导。订单模块不增加Vercel后端函数。

## 托书导入
订单列表顶部“导入托书”支持 JCT 和铁大大 Excel 模板（xls/xlsx，10MB 以内）。在本机后台线程识别，预览后进入完整表单，点击保存才写入云端。未知模板拒绝导入；缺失字段留空；报价保留原文；原文件暂不作为附件上传。

新订单号：Eurasiago-YYMMDD-6位字母数字识别码，日期按北京时间生成。客户托书号独立保留为客户参考号；编辑已有订单不改号。

## 正式客户入口
`/client.html` 为公开登录外壳，所有客户数据由 Supabase 登录及数据库 RLS 保护。客户登录独立于内部工作台会话。内部“客户账号”创建公司并授权邮箱；客户注册并验证邮箱后生效。详情中的“关联客户公司”将已有订单归属到公司，空归属订单对客户不可见。撤销邮箱授权后，该邮箱下一次请求立即失去客户数据访问权。

客户提交通过受限 RPC 生成订单，固定状态待确认、清空费用和内部操作记录，强制使用授权公司。请求 UUID 保证同一提交重试不会重复建单。内部订单更新后，仅收发通、货物、路线、计划日期和状态等白名单字段同步到独立客户表。内部费用、待办、日志、备注和通知邮箱不对客户开放。实际运踪事件、附件上传、客户自行编辑订单与邮件通知未接入。

数据库验证已覆盖两家公司互相隔离、未验证邮箱不可访问、提交重试幂等、总重导入、内部状态同步以及私有字段不泄露。测试账号和订单均在事务回滚中清除，未发送邮件。
