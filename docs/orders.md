# 订单管理

入口：运输管理 → 订单管理（`/orders.html`）。沿用工作台登录和两个现有管理员的权限。

订单保存至 `freight_booking_orders`；不导入预览站的本地样例，不改动旧 `orders/customers/quotes` 表。托书、收发通、包装、服务要求、费用和操作记录同票保存。修改采用版本检查，发生冲突时拒绝覆盖并保留未提交表单。

每次读取100票，按需“加载更多订单”；前端每页20票。搜索、筛选及统计针对已加载订单。通知人同收货人按实时资料展开。重量、体积在明细完整时汇总，否则保留填写的托书总数。

本次范围：新建/编辑/查看、批量状态、CSV导出、操作记录、应收预估费用。自动Excel解析、附件上传、邮件发送、采购成本及正式结算联动尚未接入，页面如实提示。原型费用只能作为待确认应收，不作为正式发票。

`orders-ui` 为可维护的React源文件，`build-orders.mjs` 构建脚本输出独立JS/CSS并限定样式作用域。所有私有页面仍经服务器鉴权和工作台登录引导。订单模块不增加Vercel后端函数。
