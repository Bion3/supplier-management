# 获客邮件整改：入口与发送流程

本次将客户目录、展商目录、区域企业、地图已入库名单连接到现有邮件系统。选择通过当前账号的临时会话传递（30分钟失效），只保存公司编号；邮箱和联系许可由邮件页重新读取，服务器发送前继续核对。

## 实现范围

- 各获客列表“写开发邮件”，客户单行与详情发信入口。
- 邮件筛选复用 CRM 开发阶段、重点关注、来源与采集批次。
- 新邮件默认允许每公司多个邮箱；可按需勾选每公司仅一个，跨公司相同邮箱仍去重。
- 新邮件预览跳过停止联系、未核实、重复邮箱、近期已发送、在队列中或结果不确定的地址，显示明细；近期窗口默认14天，可调整或关闭。
- 预览整批选中邮箱，保存草稿后分段调用既有后台批次接口（每次最多1000），不再按单封前台发送。未提交项保留草稿，异常后重新读取发送状态，不自动重发。
- 客户详情按时间展示最近100封发件与100封收件；收件箱可回到关联客户跟进。
- 企业线索页选择与“是否可核实官网”解耦，同时保留官网补全的独立资格检查。

## 验证

- `npm run check`：通过。
- `npm run build`：通过，构建包含新增邮件计划测试及现有邮件批次、筛选测试。
- `node --test tests/mail*.test.js tests/page-session.test.js`：42项通过。
- Chromium + Playwright 模拟流程：CRM选中 → 邮件选择传递 → 同公司多个邮箱 → 保存模板 → 多模板随机预览 → 跳过明细 → 后台批次请求 → 刷新任务仍在；展商、企业线索、收件页无脚本异常。使用模拟账号和拦截接口，没有发出真实邮件。
- 全量测试中的4项成本报价断言在修改前基线同样失败，不属于本次改动。初次缺失依赖导致的登录入口测试失败，在 `npm ci` 后通过。

## 边界与后续

- 本次复用现有数据库、队列和收件同步，无数据库迁移。
- 近期联系、可选的每公司单邮箱是新邮件预览规则；尚不是跨浏览器并发提交的数据库级限制，历史草稿批量入口继续使用原有校验。
- 自动更新开发阶段、识别自动回复并暂停后续跟进、原邮件线程内回复、按发送任务统一暂停/继续，尚未在本次实现。
- 生产环境实际 SMTP、队列执行与收件同步未以真实发送验证。本分支待合并上线。

## 多模板随机发送

模板库提供进口商开发、海外代理合作、简短需求询问、老客户跟进四类参考文案，可载入修改后保存到既有模板表供后续选择。随机模式从当前用途下勾选的模板按邮箱独立分配，预览显示模板名称，落库的草稿已保存实际主题和正文；提交或重试不会再抽取。重新生成预览会重新分配，界面明确提示。统一内容模式仍可用。模板库不将编辑框未保存修改混入随机池。
