# 运踪与时效

入口：`/tracking.html`，位于运输管理导航。沿用系统登录与团队权限。

## 数据与更新

浏览器使用本地固定版本 SheetJS 0.20.3 读取 XLS/XLSX，不执行表中宏或公式。强制从 A1 起读取，避免 B 列起始的 used range 导致字段错位。

支持国内逐站表、CIS/EU 班列工作表、异常跟进表。每份导入保存 SHA-256、来源、报表截至日及快照。先写 pending 数据，全部写完再标 complete；看板仅引用 complete 快照。较旧报告不会替换新报告，完整内容仅在打开班列详情时读取。上传重试忽略已经写入的相同行。文件和报表日期应由操作人确认。

`freight_tracking_imports` 保留导入元数据和国内参考节点；`freight_tracking_reports` 保存班列摘要与逐箱明细；`freight_tracking_incidents` 保留原始异常状态和更新链。latest 视图以报表日期、导入时间排序，使用 security_invoker 并沿用现有 CRM 团队白名单。superseded 可保留解析修正前的无效版本，避免错误数据进入看板。

## 身份和计算

- DB 使用 WB 日期与服务编号；RTSB 旧模板使用 XIAN 服务编号加 WB 日期，新模板使用完整 WBE 编号。同日多列不合并。
- 国内发运仅在运营商、月日、年份和境内外候选都唯一时自动关联；编码日期只作归组，不能代替实际 ATD。
- 全程以实际西安发车至“同班同目的站所有箱的最后实到”计算；缺任一实到不进入该目的站全程样本。ETA 与顶部正常箱 Latest 不填充逐箱实到。
- 口岸停留为顶部正常箱 latest ATA 至 latest ATD；独联体段参考为该 latest ATD 至该目的站所有箱的最后 ATA Mala；欧洲段为该目的站首个 ATD Mala 至最后 ATA DEST。字段不齐或时间逆序时不计算。
- 运营商表未标注时区，时差按原表钟表值近似。样本不按箱数重复加权。P90 使用 nearest-rank，前后期任一少于三样本时不判断趋势。
- 在途阶段结合逐箱欧洲节点与班列独联体节点推定，不代表拆分各 Part 同址。超过90天缺实到的历史记录显示待确认；不是实时列车定位。
- 异常连续空白行继承本条箱与班次，并保留进展。“维修完成”与 Finished=No 同时出现时不擅自改为关闭。

初始附件：DB / RTSB 报表至 2026-10-30，XIAN 独立来源至 2026-10-29，国内文件实际节点最新为 2026-06-17。未注明运营商的 XIAN 不归入 DB/RTSB。

验证：`node --test tests/tracking.test.js`；生产构建已纳入该测试集。

每日增量导入：freight_tracking_incremental.sql 在基础脚本之后执行。不可变内容版本由服务端按去掉文件名、报表日期后的标准 JSON 内容指纹去重。observations 只记录每天出现过哪些版本；未变化内容不重复保存。未完成导入不进入 latest 视图，失败可重试。Worker 每次只展开一张工作表，小批量等待数据库确认后继续，终止 Worker 即释放解析堆；预览只留计数、班次索引和 File 句柄。列表只拉所选时期和前一期摘要，明细仅点开加载，最近导入记录上限50。原始 Excel 解压仍会占用短时内存，单文件上限30MB；并非流式读取 XLSX 压缩包。
