# 货代CRM第一阶段

入口 `/crm.html`，与供应商系统共用登录会话和已授权账号。

支持公司搜索、新增及编辑、联系方式新增及有效性核实、历史运输回顾、来源原文查看、沟通结果与下次联系日期。今日及逾期列表取每家公司最新一条沟通记录的下次联系日期。

导入按公司名称去除首尾空格后完全一致归档。公司角色和合作状态初始为“待核实”，不从旧运输记录推断当前需求。邮件和电话仅是候选联系方式，不猜测联系人姓名。提货电话可能属于工厂、仓库或司机。

数据在 `freight_companies`、`freight_contacts`、`freight_sources`、`freight_shipments`、`freight_followups` 中保存。原有供应商和其他CRM表保持独立。初次建表脚本在 `database/freight_crm.sql`，已应用到当前Supabase项目，不应重复执行。CRM策略复制建表时 `supplier_hub_access` 的明确账号范围，后续新增账号时需要同步CRM策略。

原始名单和导入数据不放入前端资源或Git仓库。每条历史运输关联来源表和原始行号。原表cont_size保留原值及空值，不把拼箱推定为整柜数量。

本阶段暂不包含报价、订单、利润核算和自动发送消息。提醒在工作台显示。

验证：`npm test`、`npm run build`，数据库导入数量与权限读写测试。用户实际密码登录与跨设备验证需要真实用户会话。
